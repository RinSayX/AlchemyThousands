## 装配与结算规则

每炉最多两件消耗品，不同effect_category各一件；相同ID或相同类别均拒绝，即使某件当前未匹配策略/属性。success类稳丹符与温火符不能同炉，quality类聚灵符与九转丹引不能同炉，refund类护炉玉与冰魄玉不能同炉。extra双生符、research研究香各一件。8种物品共25种合法双件。

互斥以内容声明的类别为准：温火符既加成功又转移品质，但类别仍为success，可与quality类聚灵符组合。各件分别应用原标签/策略条件，未激活仍会消耗。两件按稳定ID升序处理，交换界面槽位不会改变概率、品质转移、费用或随机结果。

处理顺序为丹炉、异火、两件消耗品、传承/世界、天赋、策略；每件内部good→superior→legendary转移顺序不变。成功率5%～95%，返还/多丹0～100%，研究奖励按实际激活项相加。抽取仍为成功→品质→可选异变→可选多丹，不因增加槽位添加抽样；多丹仍最多两枚，沿用同一品质/异变，只发一次成长和首次品质奖励。

所有药材与两件物品在完整校验后统一扣除，缺少第二件不能先花第一件，失败炼制也各耗一件、符箓不返还。输出/成长溢出时回滚材料、两件、统计、操作号与RNG。预览纯计算，披露完整两件消耗/缺口和合价，非商店来源或合价溢出记null而非免费。

## 接口与界面

新增ConsumableLoadout纯校验器，复用给炼丹和购买入口：

```gdscript
var setup = {"strategy": "stable", "consumable_ids": ["consumable_wendan", "consumable_juling"]}
session.preview("recipe_juling", setup)
session.quote_consumables(setup)
session.buy_consumables(setup)
session.begin_brew("recipe_juling", setup)
```

旧`consumable_id: String`仍支持，旧字段数组仍拒绝。新`consumable_ids: Array`接受0～2个有效非空字符串，不接受同类、重复、错误类型或和旧字段混用（空字段也不例外），失败INVALID_SETUP。空列表等于不带，一项列表等于原单件；旧接口快照setup形状保留，列表接口规范为ID升序。Rules.calculate末尾增加可信可选第二件参数，第一件来源consumable，第二件consumable_2；普通调用省略它保留旧结构与计算。

quote_consumables查询所选每种各1件的权威购物车，buy_consumables重查后调用ShopService.buy_batch，一次提交。无选择NO_CONSUMABLES，第二件境界不够、合计资金不足、库存溢出均不部分购买；药材无需先齐。库存已有物品不会抵这次明确的“各买一件”数量。处理中BUSY，购买仍复用既有操作ID与自动保存方式。

炼丹房新增第二个消耗品下拉，两槽默认空。第二槽同类项禁用并标注，改变第一槽时清掉不相容的第二槽；只选第二槽也能使用。预览列两件/合价，按钮“购买所选各一件”显示总费用，统一购买刷新库存和开炉资格。炼制时两槽与购买锁定，重复点击不双扣；回执/最近炉次显示实际两件耗材。右侧滚动可到费用和概率，开炉固定在底部；960×540最小窗口仍可操作。

沿用schema2，无新增run/meta必需字段，不保存UI临时选择、不补发消耗品。旧单件已结算快照继续保留，不重算历史。新快照setup.consumable_ids记录规范列表，consumed记录两件各1；SaveManager检查列表类型/引用/类别/数量/顺序及实际消耗对应，非法回执不能覆盖有效存档。新开炉与购买沿用普通行动原有的自动保存边界；本批没有改变通关后复合事务的先保存后切换方式。
