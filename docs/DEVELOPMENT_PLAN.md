# 16. 开发阶段、交付物和验收标准

## 16.1 阶段总览

| 阶段 | 目标 | 可验收交付物 | 依赖 |
|---|---|---|---|
| P0 | 工程初始化 | 可启动项目、主菜单占位、测试入口 | 无 |
| P1 | 静态数据 | ContentDB、样例配置、验证器 | P0 |
| P2 | 背包与经济 | 交易服务、购买出售和测试 | P1 |
| P3 | 炼丹引擎 | 概率预览、执行、结果、测试 | P2 |
| P4 | 炼丹界面 | 可交互炼丹房和反馈 | P3 |
| P5 | 资源循环 | 商店、委托、探索、保底 | P4 |
| P6 | 单周目成长 | 晋升、天赋、基础图鉴、标准结局 | P5 |
| P7 | 轮回系统 | MetaSave、传承、变数、多周目 | P6 |
| P8 | 内容与平衡 | 目标内容量、隐藏结局、平衡报告 | P7 |
| P9 | 发布打磨 | 美术音效、稳定性、双平台打包 | P8 |

## 16.2 P0：项目初始化

**任务**：创建目录、`project.godot`、主场景、主菜单占位、基础主题、必要 Autoload、测试启动脚本与 README。

**验收**：Godot 能打开并运行，界面可显示，脚本解析无错误，提交 Git。

## 16.3 P1：数据与校验

**任务**：建立 JSON 内容格式和 `ContentDB`；至少 6 丹方、8 材料、3 丹炉、2 异火、3 消耗品；完整引用验证。

**验收**：通过 ID 查询内容，故意插入非法配置能够报告错误，内容测试通过。

## 16.4 P2：经济服务

**任务**：背包堆叠、材料购买、丹药出售、灵石结算、通用错误返回；不要求正式商店 UI。

**验收**：价格正确、失败不改状态、负余额和负库存不可能出现。

## 16.5 P3：概率炼丹引擎

**任务**：装备加成、策略、成功率、品质判定、失败回收、奖励、随机种子、统计测试。

**验收**：预览和执行使用同规则；可复现；材料正确消耗；10 万次统计验证。

## 16.6 P4：炼丹房 UI

**任务**：丹方选择、材料缺口、装备和符箓、概率与成本展示、开炉、结果和日志。

**验收**：玩家无需调试控制台即可完成“买材料—炼丹—售丹”原型流程；点击防抖。

## 16.7 P5：委托与探索

**任务**：委托生成与交付、探索事件、免费采药、品阶商品解锁。

**验收**：无资源永久卡死；任务不能重复领奖；秘境奖励分布可测。

## 16.8 P6：单周目完成

**任务**：完整品阶、解锁、三次天赋抉择、最终考核、图鉴、正常结局。

**验收**：一周目从丹童到大宗师可完整走通，剧情可跳过，至少能保存／读取。

## 16.9 P7：轮回

**任务**：历史纪录、传承解锁与装备、变数生成、轮回确认和安全存档。

**验收**：第一世结束 → 保存 → 继承 → 第二世初始化 → 炼丹，所有状态正确。

## 16.10 P8：内容与平衡

**任务**：扩充至目标道具量、补充隐藏结局和试炼、模拟经济、实测时长。

**验收**：正常流程可 4～8 小时完成，二周目约 2～3 小时为目标，存在明显不同的流派体验。

## 16.11 P9：打磨与发布

**任务**：替换占位资源、音效、存档迁移、异常提示、性能、Windows/macOS 构建。

**验收**：双平台离线可玩，无阻断性存档和结算 Bug，完成发布候选清单。

### 每阶段统一交付要求

Codex 每阶段必须输出：

1. 本次修改的文件清单。
2. 已实现功能和未实现部分。
3. 自动化与手工测试**实际执行的命令及结果**。
4. 遇到的问题与解决方法。
5. 对设计文档的必要变更。
6. 推荐 Git 提交说明。

# 19. 风险、决策和待验证问题

## 19.1 高风险点

| 风险 | 影响 | 对策 |
|---|---|---|
| 核心炼丹操作过于单调 | 玩家不愿意完成首周目 | 先做垂直切片，验证装备与策略选择是否有趣 |
| 概率造成主线卡死 | 玩家沮丧、弃游 | 研究心得、稳定保底、任务替代路线 |
| 灵石体系破产 | 游戏无法继续 | 免费基础材料、委托保障、经济模拟 |
| 流派只换数字不换玩法 | 多周目吸引力不足 | 每流派至少一种独特规则／任务优势 |
| 传承数值膨胀 | 失去随机张力 | 限制栏位，优先规则变化而非永久叠数值 |
| 一次性生成过多代码 | 维护困难、Bug 难定位 | 严格按阶段实现并提交测试 |
| 内容量大于开发能力 | 项目拖延 | 先 20～40 分钟原型，再逐步扩展 |
| 存档被轮回覆盖 | 永久数据丢失 | 安全存档、轮回确认、备份与回归测试 |
| 配置引用失效 | 启动或炼丹崩溃 | ContentValidator 与自动化检测 |

## 19.2 需要实际测试的假设

- 单炉 5～15 秒是否足以产生“期待感”而非枯燥。
- 成功率与品质率的 UI 文案是否容易理解。
- 冲品流是否有足够收益与独特体验。
- 首周目 4～8 小时是否过长；若核心循环单薄，应主动缩短而非堆重复任务。
- 多周目 2～3 小时是否依然令人愿意继续。
- 稀有材料的探索比例是否恰当。
- 委托是否过于繁琐。

## 19.3 已做决定与可调整项

**当前确定**：单机离线；炼丹核心；灵石货币；没有完整灵田；Godot 4 + GDScript；首周目 4～8 小时；轮回继承；概率透明；先开发垂直切片。

**可调参数**：成功率上下限、具体丹药价格、丹师经验门槛、丹炉及异火效果、主线时长分配、传承栏位、秘境权重和具体美术风格。调整这些参数应同步修改 `BALANCE.md`。

## 最终设计结论

《百炼成丹·我要成为天阶炼丹大宗师》的商业与游玩吸引力不应建立在“玩家不停碰运气”上，而应建立在以下闭环：

**公开的随机炼丹 → 不同风险收益策略 → 有意义的丹炉/异火构筑 → 可控制的丹师成长 → 可选的轮回规则变化。**

第一版优先证明“炼一炉”好玩；第二步证明“从丹童到大宗师”有成就感；第三步证明“第二世选择不同传承和流派”确实带来另一种体验。只要按这个顺序开发，就能在可控的独立游戏体量下，保留核心概率玩法和多周目重玩价值。
